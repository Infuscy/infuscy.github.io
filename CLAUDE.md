# infuscy.github.io

Jekyll + GitHub Pages frontend for static Bacalaureat data reports. Reports are pre-built Vite apps committed into subdirs; the Jekyll layer is the card grid that links to them.

## Commands

| Command | Description |
|---------|-------------|
| `bundle exec jekyll serve` | Local preview at http://localhost:4000 |
| `JEKYLL_NO_BUNDLER_REQUIRE=1 ruby C:/Ruby40-x64/bin/jekyll build` | Local build on this machine: `bundle` is broken under git-bash (MSYS path mangling + Gemfile pins conflict with Ruby 4.0's installed gems). This skips bundler and works. Output in `_site/` (gitignored). |
| `npm run build` (in a report's own repo) | Build a report -> `web/dist/` to copy here |
| `py scripts/verify_digests.py` | Data guard: recomputes canary stats from `_verify/*_slim.parquet` vs the shipped JSON (also CI: `verify-data.yml`) |
| `py scripts/check_links.py _site` | Fail on broken internal links in a build (also CI: `site-build.yml`) |

## Architecture

```
_posts/           # one markdown post per report -> grid card (post URLs only redirect to the report)
_includes/        # Jekyll partials (nav, about, footer, portfolio_grid)
bac2025/ bac2026/ bac2526/   # pre-built Vite static apps (committed, not Jekyll-built)
_verify/          # slim candidate-level parquets for the data guard (unpublished: `_` dir)
translated/       # novel chapters: *.md sources (excluded from the site) -> *.html (generated whole by scripts/sync_novel_html.py)
novel/            # the novel's contents page (standalone cover + searchable list) and chapters.js
fire-to-future/   # FIRE TO FUTURE web edition: generated chapter pages + reader.css (scripts/build_fire_to_future.py), hand-written index.html (cover + contents)
romania-deficit/  # web edition of the RomaniaDeficit DSA report (generated: page + figuri/ + PDF + Excel)
old-magic/        # The Book of Old Magic (English): generated pages from old-magic/the-book-of-old-magic.md + hand-written book.css
old-east/         # The Old Book of the East (English): generated pages from old-east/the-old-book-of-the-east.md + hand-written book.css
claude-code-2d-engines.html        # English article (lang: en) -> /claude-code-2d-engines/
claude-code-2d-engines/play/       # its three playable web builds (generated from C:/GIT/GameEngines/bench)
img/portfolio/    # card thumbnails, referenced by posts (also each report's og:image)
img/social-card.png  # 1200×630 share image for pages without their own `img`
js/site.js        # all Jekyll-layer behaviour (menu, dropdowns, section highlight, frame-buster); no jQuery/Bootstrap JS
css/reader.css    # the novel's reader theme: chapter pages + contents page (fire-to-future/ and old-magic/ have their own)
_config.yml       # site metadata, social, credits
Gemfile           # github-pages Jekyll + Ruby 3.4 stdlib backports
```

## Gotchas

- **Post `description` is plain text** — one or two sentences, shown on the card (clamped to 3 lines) and in `feed.xml`. Jekyll never escapes Liquid output, so keep HTML out of it.
- **Posts are data, not pages** — `_config.yml` defaults give them `layout: report-redirect`, so `/YYYY/MM/DD/slug/` is a noindex redirect to `/<report>/`. Each post needs a `report:` field (the report dir); sitemap and RSS link to `/<report>/`.
- **Cards are fully clickable** — the title link (`.card-link`) stretches over the card via `::after`; the "Deschide…" button is a decorative `<span aria-hidden="true">`. Any extra link inside a card needs `class="card-details"` (raised above the overlay) or it won't be clickable.
- **Theme `rem` = 16px** — `main.css` resets Bootstrap 3's `html { font-size: 10px }` to `100%`. Write sizes in `rem` assuming 16px; don't remove the reset (chapter and ToC pages depend on it too).
- **Card thumbnails are report screenshots** — 960×540 PNG in `img/portfolio/`, from headless Chrome at 1120×630, 2× DPR, of the served report (`chrome --headless=new --blink-settings=preferredColorScheme=1 --force-device-scale-factor=2 --window-size=1120,630 --virtual-time-budget=6000 --screenshot=… http://localhost:4000/<dir>/`), then resized and saved as a 256-color palette PNG (Pillow `quantize(256)`, ~50 KB). Without `preferredColorScheme=1` headless Chrome follows the Windows theme and shoots the dark mode.
- **Book cards open with a CSS cover, not a screenshot** — `.book-cover-*` in `_includes/fiction.html` + `_includes/css/main.css`: a 16:9 band in the book's own colours with its emblem and title, decorative (`aria-hidden`) and dark in both schemes like the cover pages. The ornaments are copies of the books' own (the novel's arch sigil from `css/reader.css`; Old Magic's star, rosette frieze and glazed brick from `old-magic/book.css`; Fire to Future's cog and flame and part stripe from `scripts/build_fire_to_future.py`; the Old Book of the East's cross-stitch band and emblem, printed by `scripts/old_east_stitches.py`), so when a book's cover changes, change its card too. A new book gets a `.book-cover-<slug>` in the same pattern.
- **Reports are not built by Jekyll** — to edit one, change it in its upstream repo (`C:/GIT/BAC2025IUNIE`, `BAC2026`, `BAC2526`), rebuild, and copy `web/dist/` here. Never patch the shipped `bac*/` files in place: the next upstream rebuild silently reverts it.
- **Keep the reports lean** — no in-browser SQL/DuckDB-WASM (removed 2026-10-03: ~146 MB of WASM per two reports). The report CSP is `script-src 'self'`; don't add `'wasm-unsafe-eval'`/workers back.
- **`exclude:` in `_config.yml` replaces Jekyll's defaults** — internal docs (`*.md` here), `scripts/` and `translated/*.md` are kept out of the site; keep the Gemfile entries when editing the list.
- **No inline scripts on chapter pages** — `translated/*.html` and `fire-to-future/*.html` use `/js/reader-font.js` with a `script-src 'self'` CSP. Novel chapters also have no inline styles (`style-src 'self'`): their CSS is `/css/reader.css`. `scripts/sync_novel_html.py` writes novel pages that already comply (it refuses inline styles/scripts; `scripts/patch_translated_security.py` still passes as a check) / `scripts/build_fire_to_future.py` (emits all of it, plus each page's description and canonical; its CSS lives in the script's `CSS` constant and is written to `fire-to-future/reader.css`).
- **Novel chapters: edit the `.md`, then sync** — `translated/chapterN.md` is the source; `py scripts/sync_novel_html.py` renders every chapter page whole from its `PAGE` template (CSP metas, top bar with font controls, disclaimer, chapter, Translator Notes, a pager naming the neighbouring chapters, footnote) and rewrites `_data/novel_chapters.json` (`--check` only reports). It also sets the page in book typography — curly quotes and apostrophes, ` -- ` → em dash, `...` → ellipsis — renders `>` blocks (a letter, a song) as blockquotes, and marks each opening paragraph (small capitals; a drop cap only when it is ≥ 180 characters and starts with a letter). The `.md` keeps straight quotes; never hand-edit the `.html`. Don't use `scripts/build-novel.js`: it regenerates whole pages from an older template and drops the font controls, disclaimers, CSP metas and the theme. Names and terms follow official WoW English; keep one spelling per character/place across all chapters.
- **The novel's theme is `css/reader.css`** — "a mage's working journal": vellum and violet ink, a candle-lit violet study in dark mode, brass ornaments; system serif stack (Palatino family), AA-checked in both schemes. The ornaments (an arch of dressed stones around a spark, the divider, the scene-break sparks) are original SVG masks — never use Blizzard art, logos or fonts. `novel/index.html` is standalone (`layout: null`, own head with a strict CSP and Open Graph tags, no site navbar) and uses the same stylesheet; `js/novel-toc.js` folds curly and straight quotes so searches still match.
- **Fire to Future's theme lives in `scripts/build_fire_to_future.py`** — "a field manual on the workshop bench": the drafting paper and carbon ink of the book's own figures, set like its print edition (Cambria-family serif, ochre spaced capitals, a steel rule under each title); dark mode is the workshop at night, with the figures kept as paper (their SVG is dark ink). Each part has an accent on the fire-to-future journey (`--p1` ember … `--p5` blueprint blue, `--annex` gunmetal), picked by `data-part` on `<body>` and on each contents group. The script's `CSS` constant (icons filled in by `css_text()`) is written to `fire-to-future/reader.css` and styles both the chapter pages and the hand-written cover/contents `fire-to-future/index.html` — edit the constant, never the `.css`, then re-run the script. It also adds reading markup that never changes the text: part/chapter kickers, a spec plate (`dl.spec`: difficulty gauge, chapter chips) from each chapter's metadata blockquote, `.sec-num` section numbers, a pager naming the neighbouring pages, and callout signs. The emblem (cog around a flame, `EMBLEM_PATH`) is repeated inline in `index.html`. The contents list is rendered by Liquid from `_data/fire_to_future_chapters.json` (`part_key`, `part_desc`, `minutes` come from the script); `js/fire-to-future-toc.js` only filters it. AA-checked in both schemes; keep the Gate/Warn/Hazard callouts the loudest boxes on the page — they carry the book's safety gating.
- **Use `xml_escape`, not Liquid's `escape`** — Liquid 4.0.3's `escape` calls `String#untaint`, which Ruby 4.0 removed, so the local `jekyll build` fails on it (GitHub Pages' newer Liquid would not).
- **`romania-deficit/` is generated** — `py scripts/build_romania_deficit.py` renders `C:/GIT/RomaniaDeficit/Raport_Romania_Deficit_Sustenabilitate.md` with that repo's own parser (`tools/md_comun.py`, shared with its DOCX/PDF) and copies the figures, PDF and Excel. Edit the report upstream, regenerate its PDF there (`python tools/genereaza_raport.py`), then re-run the script; never hand-edit `romania-deficit/index.html`. The script publishes the figures as lossless WebP (needs Pillow) and writes `date_published` from the report date. The upstream repo is private, so links to its code/CSVs/sub-reports render as plain text. The body is wrapped in `{% raw %}` so Liquid never touches report text. The civic card in `_includes/civic.html` repeats the date and reading time — update it when they change.
- **The civic analyses share `css/civic.css`** (hand-written) — "the public record": a serif text column of ~75 characters, sans-serif for data and apparatus, tables and figures in a wider column, the notes under the byline as a ruled panel with the AI-transparency note (`.nota-ai`) marked in the accent — keep it that visible (EU AI Act art. 50(5)). Both pages set `css: /css/civic.css` in front matter (`_includes/head.html` links any page's `css:` after `style.css`) and use `.articol.civic` plus `.civic-deficit` (ledger green: ledger-ruled tables, figure columns `td.num` right-aligned, a double rule over the summary) or `.civic-parcari` (road-sign blue: the P sign, `blockquote.lege` for quoted law and `.schita` for proposed text, `.forta[data-forta="1"–"5"]` strength meters, `.pasi` steps timeline, `.termen` deadlines). The deficit page's markup comes from `build_romania_deficit.py` (section numbers, `num` columns, and `.scen-s1`…`.scen-s7` marks whose colours it reads from the model's `CULORI_SCENARII` in `model/model_dsa.py`, so text and charts match; citations `[Sn]` are never marked). `art47-hcl419.html` is hand-written: those classes are markup only — its wording must not change. Main.css's dark `body .articol` overrides skip `.civic`; the engine article keeps the old article look.
- **`claude-code-2d-engines/play/` is generated** — `py scripts/build_engine_demos.py` copies the Phaser, Godot and Defold web builds from `C:/GIT/GameEngines/bench/*/builds/web`, adds a per-page CSP (sha256-pinned inline scripts), the referrer meta and a `LICENSES.txt` (Godot's notices come from its 4.7.2 console exe). Never hand-edit the copies: re-run the script. Its `.gitattributes` (`* -text`) keeps the builds byte-exact under `core.autocrlf`, which the CSP hashes depend on. Godot's 38 MB build is the one deliberate exception to "keep it lean": it loads only when a reader opens it. The article's "Play the three builds" box (`#play`, styles in the page's own `<style>`) shows one card per build with a screenshot of it in play — `img/engine-builds/{phaser,godot,defold}.webp`, 640×360 (~3–5 KB), each cropped to a 16:9 band of the playfield from the served build started with `?seed=42` — and the controls as `<kbd>` keycaps. Retake a screenshot if its build's look changes; they are decorative (`alt=""`), the link text names the build.
- **`old-magic/` is generated** — `py scripts/build_old_magic.py` turns `old-magic/the-book-of-old-magic.md` (the book's Markdown export; excluded from the site) into one page per `##` section, the cover/contents `index.html` (front matter puts it in the feed and sitemap) and `_data/old_magic_pages.json` (sitemap). It only adds reading markup (catalogue cards, clay-tablet incantations, line-number gutter, "Today" callouts, chapter cross-links), never changes the text; never hand-edit the pages. A spell's original goes in a `**Akkadian (…).**` or `**Sumerian (…).**` paragraph right after its English (several in a row are fine; the script attaches them to the tablet with `lang="akk"`/`"sux"`): words in `*italics*`, logograms and the marks ÉN, TU₆ ÉN, KA.INIM.MA outside them so they stay upright, determinatives as `<sup>d</sup>`, and the caption names the edition the lines were checked against (no originals from memory). `old-magic/book.css` is hand-written (clay/lapis/carnelian theme, both colour schemes AA-checked); the script never touches it. The book's share image `img/social-card-old-magic.png` (1200×630, used by every book page) is rendered by `py scripts/make_old_magic_card.py` (headless Chrome, title and subtitle read from the Markdown): re-run it when they change.
- **The book's font is a renamed Gentium subset** — `old-magic/fonts/old-magic-text-*.woff` ("Old Magic Text", ~40 KB each) are subsets of Gentium Book Plus 6.101 (SIL, OFL 1.1), chosen because it has every transliteration letter (ḫ ṣ ṭ, subscript digits; Palatino, Georgia and Sitka lack ḫ ṣ ṭ). The OFL reserves the name "Gentium" for unmodified fonts, so never rename the subsets back; keep `fonts/OFL.txt` next to them. Remake them with `py scripts/subset_old_magic_fonts.py --src <dir>` from the four TTFs + OFL.txt of github.com/google/fonts `ofl/gentiumbookplus` (not committed). `build_old_magic.py` warns when the text uses a character the subsets lack. WOFF, not WOFF2: fontTools needs the brotli module for WOFF2.
- **`old-east/` is generated** — `py scripts/build_old_east.py` turns `old-east/the-old-book-of-the-east.md` (excluded from the site) into one page per `##` section (introduction, anatomy, calendar, `book-1`…`book-6`, bestiary, sources), the cover/contents `index.html` (front matter: feed and sitemap) and `_data/old_east_pages.json` (sitemap). It only adds reading markup, never changes the text; never hand-edit the pages. Its conventions: `### I.1 Name — gloss` entries (anchors `#i-1`; "I.4" and "Book V" in the text become links), the italic line under an entry is `.where`, and the bold leads `You need:`, `The words…`, `Age: <rating>.` and `Safety…` become the materials panel, the "towel" panel, the evidence note and the warning callout. A charm given as blockquotes (all-italic original lines, then the English) is paired line by line, en face on wide screens. The `Age` gauge reads the rating's first clause: Ancient → 4 diamonds, Medieval/Early modern → 3, Folk-recorded → 2, Local/revived → 1. Keep `Safety` before `Age`, and before the steps when the steps handle something dangerous. Italics with ă â î ș ț get `lang="ro"`.
- **Old East's theme and ornaments** — `old-east/book.css` is hand-written: linen and soot ink with madder-red small-capital rubrics (the red of the old church books), Voroneț-blue links, black homespun wool in dark mode, the cover in madder red; AA-checked in both schemes, and the `Safety` callout stays the loudest box. The cross-stitch motifs (band, divider, the "sown field" emblem, the top-bar mark) are text grids in `scripts/old_east_stitches.py`: the build and card scripts import it for the inline emblem, and `py scripts/old_east_stitches.py` prints the data URIs that `book.css` and the home card in `main.css` carry, so re-run it and paste when a motif or thread colour changes. The font is "Old East Text" (`old-east/fonts/`, ~60 KB per style), another renamed Gentium Book Plus subset with Cyrillic (the curses) and the small capitals (`smcp`, `c2sc`): `py scripts/subset_old_east_fonts.py --src <dir>`, same sources and OFL rules as Old Magic's. Its share image `img/social-card-old-east.png` comes from `py scripts/make_old_east_card.py`.
- **English pages** set `lang: en` in front matter; `page.html` and `head.html` switch `<html lang>`, the skip link and `og:locale` on it.
- **Gemfile pins `csv`, `bigdecimal`, `base64`, `drb`, `mutex_m`** — Ruby 3.4+ removed these from stdlib; old `github-pages` Jekyll needs them. Don't delete them.
- **Push to publish** — GitHub Pages builds automatically on push to `master`.
- **Contact is a plain `mailto:` link** (GDPR decision) — no forms, no Formspree, no Disqus, no third-party processors. If a contact form is ever added again, it needs consent handling + a documented processor in `privacy.html`.
- **Content pages are HTML, not markdown** (`privacy.html`, `novel/index.html`). Kramdown's `parse_block_html` is off, so markdown inside a `<div>` renders as raw text — the old `privacy.md` was broken exactly this way. Keep content pages as `.html` files.
- **Frontend JS stack: none.** jQuery and Bootstrap's JS were removed (2026-11-17); `js/site.js` (plain JS, `defer`) runs the mobile menu, the dropdowns (click, Esc, arrow keys), the section highlight, the shrinking navbar, the scroll-to-top button, the deficit page's floating "Cuprins" pill and the frame-buster. It toggles Bootstrap 3's class names (`.collapse.in`, `.dropdown.open`, `.active`) because the CSS styles those. The themed Bootswatch CSS is 3.2.0 — it's customized with the report design tokens, so upgrade it only by re-applying the custom colors. Don't add `data-toggle` markup: nothing reads it.
- **Icons are inline SVG** — `{% include icon.html name="…" %}` (1em, `currentColor`). Font Awesome 4.1 was removed: it lacked half the icons the site used and cost ~105 KB per page. Add a new icon as a `when` branch in `_includes/icon.html`; no icon fonts, no `fa` classes.
- **Nav section highlight and dropdowns** — each top-level nav `<li>` names its home-page section in `data-spy="<id>"`; `js/site.js` marks the one in view `.active`. Dropdown toggles link to their section (`/#civic`), so they still go somewhere without JS.
- **Dark mode follows the system setting everywhere** (no toggle, nothing stored): the `@media (prefers-color-scheme: dark)` block in `_includes/css/main.css` (with `body .articol:not(.civic) …` overrides, because article pages set colors in their own later `<style>`; the civic pages' dark tokens are in `css/civic.css`), the tokens in `css/reader.css` and in `build_fire_to_future.py`'s `CSS`, and each report's `web/src/index.css`, which remaps the exact Tailwind color utilities the report uses — a new color utility in a report needs a dark entry there. New colors anywhere: check WCAG AA (4.5:1) in both themes.
- **Feed, sitemap and JSON-LD come from front matter** — an article page carries `date_published` (+ `date_modified`, `feed_category`) and is then in `feed.xml`, the sitemap (with `lastmod`) and gets `Article` JSON-LD (`_includes/structured_data.html`); posts can carry `date_modified`. Pages without `img` share `img/social-card.png`.
- **Report apps (upstream)** — displayed numbers go through `nf()` (`web/src/lib/format.ts`, ro-RO: 107.812, 7,63), never a bare `toFixed`; ready-made sentences from the pipeline go through `roNumbers()`. Text is Romanian with diacritics. Each report's `web/index.html` holds its title, description, canonical and Open Graph tags, and the header/footer link back to `/` and to the other reports. Tabs after the first load lazily (`React.lazy`). `Card` (`ui.tsx`) drops its default `bg-white`/border when `className` sets its own: Tailwind's stylesheet order, not className order, decides which of two backgrounds wins. The county map has no tile layer, so the reports make no third-party requests — keep it that way (the privacy page says so).

## Compliance (check before publishing anything user-facing)

Before adding content or changing site behavior, check the relevant EU/Romanian legal obligations and resolve them up front — the same way the article and the novel got their disclaimers.

- **AI-generated content (EU AI Act, Reg. (EU) 2024/1689, Art. 50)** — transparency obligations apply **from 2 Aug 2026**. Any text published to inform the public **on matters of public interest** that was generated/manipulated by an AI system must be **visibly disclosed** as such (Art. 50(4)), unless **both** apply: (a) the content underwent substantive **human review / editorial control** (fact-checking — not spell-checking), and (b) a natural/legal person holds **editorial responsibility** (their identity + contact must be findable — see [Commission Guidelines](https://ec.europa.eu/newsroom/dae/redirection/document/131215)). Disclosure must be clear, distinguishable and at first exposure (Art. 50(5)); machine-readable marking (Art. 50(2)) is the AI *provider's* duty, not ours. **Default policy: add a voluntary visible transparency note** (AI assistance + human verification + responsible person/contact) — pattern in use: `art47-hcl419.html` and `romania-deficit/` (Transparență note by the byline + footer mention).
- **Personal data (GDPR + Romanian Law 190/2018)** — current decision: no forms, no third-party processors, no analytics/fonts/external embeds, no third-party requests at all (the report maps dropped their OpenStreetMap tiles on 2026-11-17) (see Gotchas). Verify anything new that touches personal data or makes third-party requests.
- **Copyright** — only original/own or clearly licensed content (text, images, data, code); keep the non-commercial fan-work disclaimers on derivative works (`fire-to-future/`).
  - **The novel (`/novel/`, `translated/`) is a known, accepted exception — not an issue to raise in reviews.** It's an unofficial translation of an old Chinese web-novel fanfic; getting a licence is practically impossible, and the owner accepted the risk (see `SECURITY.md`). Keep its disclaimer + takedown-on-request note.
- **Other rules to sanity-check per feature** — accessibility (required for Art. 50(5) info too), consumer/marketing rules (Law 363/2007 — only if ads/sales are ever added), and any new EU/RO law that imposes a notice, disclaimer, or consent.
- **Verify from primary sources** — EUR-Lex for the regulation text, Commission guidelines for interpretation; note dates carefully (entry into force ≠ date obligations apply). When uncertain about whether a duty applies, add the voluntary notice anyway (cheap, honest, and it satisfies the strictest reading).

## Workflow: adding a report

1. In the report's repo: run the pipeline (`py preprocess/build_data.py`, `py analyze/stats.py`, `py preprocess/export_findings.py`), then `npm run build` in `web/` -> `web/dist/`.
2. Copy `web/dist/` into this repo as a new subdir (e.g. `bac2027/`), and the repo's `data/bac_slim.parquet` to `_verify/bac2027_slim.parquet` if the data guard should cover it.
3. Add `_posts/YYYY-MM-DD-slug.markdown` with `report: <dir>`, `img`, `category`, `project-date`, `stats` and a plain-text `description` (no `layout:` — the default handles it); add `date_modified` when the report is updated later.
4. Add a screenshot thumbnail to `img/portfolio/` (see Gotchas).
5. Build, `py scripts/check_links.py _site`, `py scripts/verify_digests.py`, then push.
