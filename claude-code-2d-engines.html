Game development · Claude Code · October 2026

Which engine for small 2D games on mobile, web and Steam, if Claude Code writes the code?

Short answer: Godot 4.7 with GDScript. Claude Code built the same small 2D action game in three engines, and each one was then taken as far toward Steam, Google Play, the App Store and the web as a single Windows PC allows. Godot came first overall and on Steam, and is tied for first on Android and iOS. Pick Phaser 4 instead if the browser is your main platform, and Defold if the smallest possible download or a later console release matters more than anything else. All three builds are playable in your browser.

The short version

  • Pick Godot 4.7 (GDScript) if you want one project that ships to Steam, Google Play, the App Store and the web. It scored 4.47 out of 5, against 4.18 for Phaser 4 + Capacitor + Electron and 3.89 for Defold 1.14.
  • Claude Code can build a working game in all three. Each engine got a fresh session; all three finished the same 12-point game and a follow-up change with no human help and no invented APIs. Godot needed the fewest tool calls and made no mistakes it had to correct.
  • Phaser is the pick for a web-first game (a 1.3 MB web build), but its route to Steam through Electron is heavy (358 MB) and its Steam integration rests on a young library from a single maintainer. Defold makes the smallest builds (9 MB on Windows, about 2.5 MB on Android) and has official console support, but scored lowest on graphics and on the agent loop.
  • No engine can sign an iPhone build on Windows. Every route ends on a rented Mac in the cloud, which is free for public GitHub repositories. Godot's iOS export was the most App Store-ready of the three.
  • Purchases and ads matter most among store services. Godot reaches every core service, but through community plugins, so Phaser's and Defold's plugins score higher on the mobile stores. Defold has no maintained route to Game Center or iCloud saves.
  • Caveats: nothing has run on a phone yet, no store plugin has been run, each engine got one run, and from April 2027 Apple's new SDK means every iOS game must cope with resizable windows.

1. What "best" means here

The premise is that Claude Code writes, builds and tests the game, and the human mostly reviews. So an engine is judged on three things: how efficiently an AI agent gets a correct, working game out of it; how far a Windows PC gets toward each store; and how the result looks when there is no artist and everything on screen comes from code. Only things that could be measured or looked up in documentation and source code count.

The setup is a solo developer on Windows 11 with no Mac, no iPhone and no artist, a project of 3 to 12 months, and a preference for free, open-source tools. Steam, Google Play and the App Store weigh the same; the web build is a bonus. Three engines were measured hands-on. Thirteen more were screened against documented facts (section 10).

The arithmetic is simple and the same for every engine. A check scores 5 if it passes, 3 if it partly passes and 1 if it fails. A measured quantity, such as build size or session time, scores 5 for the best engine and loses 2 points for every tenfold gap to the best. Store services, such as purchases or Game Center, are scored one at a time and weighted by evidence (section 9). Each engine ran once, so gaps of 0.15 or less are ties. Totals are computed from unrounded scores, so one can sit 0.01 away from what the rounded figures in a table add up to.

The weights follow the premise. The agent loop carries the most (35 of 120) because the agent builds the game. Steam, Android and iOS get 20 each, as three equally important stores. Graphics gets 15 because, with no artist, the engine's drawing defaults and the agent's choices are all you get. The web build and an open-source licence get 5 each, as a bonus and a preference.

Godot's lead over Phaser comes mostly from Steam, where Phaser depends on Electron and a young Steamworks library, and then from the loop, graphics and iOS; Phaser wins the web column and is level with Godot on Android. Its lead over Defold comes from graphics, the loop, Steam and Defold's non-OSI licence. On iOS the two are level, because Defold's testing tools and official store plugins make up for its weaker game features. Section 9 shows that no reasonable re-weighting changes the order.

3. The benchmark: one game, three engines

Each engine got one fresh Claude Code session (Opus 5.5) on the same Windows 11 machine on 28 October 2026. The task was "Asteroids-lite", judged against 12 checks: a title screen; a ship that rotates, thrusts with inertia, fires and wraps around the screen; asteroids that split in two twice; scoring, lives and a sound; waves that grow; game over and restart; a seed for repeatable runs; a command-line test; Windows and web builds made from the command line; and an automatic screenshot with a JSON dump of the game state. The same session then received a change request: add a pause menu and power-ups.

The headline is that all three worked. Three engines, three complete games, no human help and no hallucinated API. The scored differences are about effort. Godot's agent kept the whole project in plain text: a project file, two tiny scenes, input actions registered in code and a fixed 60 Hz simulation step, which made pause and repeatable tests easy. Phaser's agent checked every call against Phaser's TypeScript definitions, which kept API errors at zero, but its first playtest found that a very short key tap could be missed, and Electron's security settings blocked the test tool from attaching to the packaged app. Defold's agent had a Claude Code plugin for Defold, written by the author of this article (version 0.2.7, open source), that answered every API question for the installed version, yet it still made two wrong assumptions about how GUI nodes draw and needed about twice Godot's tool calls. It was the only engine-specific agent tool in the test: the Godot and Phaser sessions worked with their engines' own command-line tools, and Godot still needed the fewest tool calls.

The spread, 4.36 to 4.98, is narrow. That is the honest reading: all three are workable engines for an AI agent, and the loop separates them by degree, not by kind.

Controls: Enter to start · Left/Right or A/D to rotate · Up or W to thrust · Space to fire · Esc to pause (Resume, Restart, Quit to Title). Destroyed asteroids sometimes drop a power-up: triple shot, a one-hit shield or an extra life. Add ?seed=42 to the address to replay the same asteroid field.

Each folder includes the engine's licence notices in LICENSES.txt. The Godot and Defold builds create a small database in your browser's IndexedDB that their engines use for save files; these games save nothing in it, and nothing is sent anywhere (see the privacy page).

4. Steam

Godot and Defold export native Windows executables. Phaser runs in a browser engine, so reaching Steam means wrapping it in Electron, which bundles Chromium. The measured Windows builds were 358 MB for Phaser + Electron, 104 MB for Godot and 9 MB for Defold.

The Steam integration splits them further. The most-used Steamworks binding for Node, steamworks.js, last shipped a release in August 2024. The newer steamworks-ffi-node covers the whole API and ships often, but it is a single maintainer's 0.x project, and the Steam overlay only draws over Electron with a GPU workaround switch (--in-process-gpu). Godot uses the community GodotSteam extension, which moved from GitHub to Codeberg in 2025 and whose 20 October 2026 release includes a Godot 4.7.2 build, although no game in this test has loaded it yet. Defold's official Steam extension had a release in June 2026, but it bundles an older Steamworks SDK and has no Steam Input or Workshop calls. Every Defold native extension, Steam included, is compiled on Defold's free cloud build server, which publishes no service guarantee; the alternative is self-hosting that build server in Docker.

5. Android

All three produced a signed APK and App Bundle from the command line, targeting Android 16 (API 36), which Google Play requires, and with 16 KB page alignment, which Play requires of apps that target Android 15 or later and will enforce from 1 February 2027 by refusing updates without it. Nothing was installed on a phone or emulator in this check; it is build quality only.

Defold builds the best package; Godot ships the most complete Android game. Defold's build was flawless: one command, 7.3 seconds, nothing extra to install. Godot's package is ten times larger because the engine runtime is about 99% of it, and the agent hit three problems on the way to the Play bundle, all fixable: the Gradle daemon made the headless export hang, a template flag used on its own never exits, and a missing project icon prints an error. In exchange, Godot already has the back gesture, a call that reports the safe area inside the system bars (the game still has to lay its HUD out within it), a built-in virtual joystick and vibration, and its community billing plugin moved to Play Billing Library 9.1 in July 2026. Capacitor is the easiest to test on a device (live reload and Chrome DevTools), but its generated manifest lacks the game category and orientation lock, which Android 16 needs before it respects a landscape lock on tablets. On store services the order flips: Defold's official extensions and Capacitor's company-published plugins outscore Godot's community ones, so the three Android scores now sit within a tie of each other.

Defold got furthest: its command-line builder assembled a complete unsigned app on Windows and only stumbled at packing it, which a 0.3-second script fixed. But that app lacks the App Store icon catalog and the export-compliance key, so it still needs work on a Mac. Godot exported a complete Xcode project after one fix (it needs a 1024 px project icon) and ships every key App Store Connect expects: a privacy manifest, the scene life cycle iOS now requires, a launch storyboard, the encryption declaration, a landscape lock (taken from the project's orientation setting) and a request for 120 Hz on ProMotion iPhones. Capacitor's template is a generic app's: portrait allowed, status bar visible, and no app privacy manifest. Its web view also caps animation at 60 Hz.

Both manuals say this cannot be done: Godot's says you must export for iOS from a Mac with Xcode, and Defold's that iOS bundling is available only in the Mac editor. That holds for the editors and for a finished, signed app. These exports used the command line instead: Godot's headless --export-release, with export_project_only=true in the iOS preset, writes the Xcode project on Windows, and Defold's bob.jar builds an unsigned bundle with --platform arm64-ios.

The route without a Mac is the same for every engine: export the project on Windows, let a hosted macOS runner build and sign it, upload it, then test through TestFlight. GitHub's standard macOS runners are free in public repositories and cost $0.062 a minute in private ones after the plan's included credit; Codemagic gives individuals 500 free macOS minutes a month. The upload can run on that Mac or from Windows with Apple's Transporter tool or the App Store Connect API. You still need the Apple Developer Program ($99 a year).

Godot's weak spot is testing without a Mac: its iOS Simulator libraries shipped broken in 4.6.2 and 4.7.1 (the 4.7.2 status is unverified), and on a device the agent gets logs only. Defold is the most testable on paper, with documented Simulator builds for Apple-silicon Macs and an automation extension that compiles for iOS (not yet tried on an iPhone).

Store services pull the two together. Godot's Apple plugin covers purchases, Game Center and iCloud saves, but its first release was on 20 November 2025 and it has one maintainer. Defold has no maintained Game Center or iCloud route, and its official purchase extension still uses Apple's original StoreKit, yet its official extensions outscore Godot's young plugin where most of the weight sits, on purchases and ads. Godot and Defold end level on iOS.

April 2027: plan for resizable windows now

Apple announced on 9 September 2026 that from April 2027 every upload must be built with the iOS 27 SDK. Under that SDK, the setting Godot and Defold use to keep a game full-screen no longer stops the system from resizing it, on iPad and on iPhone alike, and the new foldable iPhone Duo makes that concrete. Whatever engine you pick, design the game to render correctly at any window size from day one.

7. The web

All three web builds ran. Phaser's was 1.3 MB, Defold's 6.2 MB and Godot's 38 MB. Godot's web export uses the WebGL 2 Compatibility renderer and GDScript only (C# projects can't export to the web), and runs single-threaded by default. That is fine for itch.io or a demo, but the first load is heavier. If instant play in a browser is the main way people will find your game, Phaser has a real advantage here. You can compare the load times yourself with the three builds above.

9. Does the weighting change the answer?

Weighting Steam the same as each mobile store is a choice, so it was checked against the 2025–26 market. By total spending, mobile is far bigger: by Sensor Tower's count, players spent about $82 billion on mobile games in 2025, with the App Store taking roughly 1.75 times Google Play's game revenue ($52.5 billion against about $30 billion), while Steam took about $17.7 billion across all its games, by Alinea Analytics' estimate. Newzoo's 2026 forecast puts mobile at 57% of the games market, consoles at 22% and PC at 21%.

For a solo indie, though, the picture flips. Mobile money concentrates in big free-to-play games with large advertising budgets; mobile game spending grew 1% in 2025 and fell 2% in the first half of 2026 (Sensor Tower again), while Steam grew 15% in 2025 and indie games took about a quarter of it, roughly $4.5 billion. In GDC's 2026 survey, 83% of developers were making PC games. Equal weights sit between these two readings, so the model was re-run with weights taken from each.

Which store services count most

Inside each store criterion, the services an engine can reach, such as purchases, ads, Play Games, Game Center or push notifications, are scored one at a time. An official, current plugin scores 5, an established community plugin 4.2, a young one 3.4, and a service with no maintained route 1. Not every service matters equally, so each gets a weight out of 100 for its store, from three kinds of evidence with equal say:

  • What people search for: Google Trends, developer questions, and the Godot and Defold forums.
  • What games use: counts of games per SDK on Google Play and the App Store, public game code, and Steam's store data.
  • Where the money goes: about two-thirds of mobile game revenue comes from purchases and one-third from ads.

The resulting weights, out of 100 per store, are whole numbers, and no service gets less than 1:

  • Google Play: purchases 36, ads 31, ad mediation 6, social sign-in 6, analytics 6, Play Games 6, push notifications 3, crash reporting 2, and 1 each for review prompts, in-app updates, asset delivery and Play Integrity.
  • App Store: purchases 40, ads 30, ad mediation 7, social sign-in 6, analytics 6, Game Center 5, push 2, crash reporting 2, and 1 each for iCloud saves and review prompts.
  • Steam: achievements 33, Workshop 23, cloud saves 14, friends and rich presence 12, Steam Input 6, DLC 6, leaderboards 6.

Purchases and ads dominate on mobile. They carry the revenue, and they lead search too: in five years of Google Trends, "IAP" and "in app purchase" searches with Unity score 1.08 if AdMob is 1, while push-notification searches score under 0.01. They also lead in shipped games: on Google Play, AdMob is in about 206,000 games, against 63,000 for Firebase push notifications and 44,000 for Play Games (42matters' SDK counts, as read on 1–4 November 2026). Push ranks low because few players opt in, about 28% on Android and 21% on iOS for games, and click rates are around 1% or less. Social sign-in is still common, but Meta has archived Facebook Login for Gaming.

On Steam, achievements come first: of the roughly 188,000 games in Steam's store search, 47% list achievements, 27% cloud saves, 8% leaderboards and 2.3% Workshop (counts read on 5 November 2026). Workshop still ranks second because players search for it heavily, probably mostly to browse mods, so its weight is likely too high for a small action game.

Godot's store plugins cover every core service, but they are community-run, and its Apple plugin still counts as young, so Phaser's company-published Capacitor plugins and Defold's official extensions score higher on both mobile stores. Defold, though, has no maintained route to Game Center, iCloud saves or Play Integrity, and its Steam extension lacks Steam Input and Workshop. If your game must have Game Center or iCloud saves, rule out Defold. Changing how the three kinds of evidence are weighted keeps Godot first, 0.26 to 0.33 ahead of Phaser. No store plugin was run for this article: a pass means the plugin documents the feature, not that it works.

How the calendar moves Godot's scores

A community plugin counts as established once its first release is a year old, so a score can step up with the calendar and no new evidence. Three of Godot's plugins cross that line within 60 days of 5 November, the day the store facts were read. Re-running the model on each of those days moves only Godot's column: Phaser stays at 4.22 on Android, 3.72 on iOS and 4.18 overall, and Defold at 4.07, 3.94 and 3.89.

10. The other engines

Engines without hands-on data were screened against the same hard requirements: a maintained route to Steam, a command-line path to a Play-ready App Bundle, a route to the App Store from Windows that survives Apple's iOS 27 rules, and preferably an open-source licence. Every one that supports iOS needs a Mac somewhere to compile and sign.

11. Getting started with Godot and Claude Code

  • Pin the version. Use Godot 4.7.2 and its export templates, and don't switch to the 4.8 beta in the middle of a project.
  • Keep the project in text. Small scenes, input actions registered in code, preload() constants instead of class_name. Put the game rules in a pure simulation layer with a fixed 60 Hz step and a seeded random generator, so every test is repeatable.
  • Give the agent a loop it can see. Headless import, unit tests with GUT, then a scripted run that saves a screenshot and a state.json the agent reads back. The benchmark measured 3.3 seconds from edit to screenshot.
  • Set a 1024 px opaque project icon on day one. It fixes an Android export error and the iOS export failure.
  • Android release builds: set GRADLE_OPTS=-Dorg.gradle.daemon=false, and pass the build-template flag only together with an export.
  • iOS: export the Xcode project on Windows and let a GitHub Actions macOS runner build, sign and upload it, with the certificates kept in repository secrets.
  • Design for any screen. Stretch mode canvas_items with aspect expand, the HUD inside the safe area, and screenshots at several sizes, from 20:9 phones to 4:3 iPads.

A short CLAUDE.md carries those rules into every session. This excerpt is the core of the one written for this project:

# CLAUDE.md (excerpt): Godot 4.7.2 + GDScript; Steam, Google Play, App Store, web

## Stack (pinned; never upgrade unless asked)
Godot 4.7.2 stable, run through a wrapper script with a timeout and a saved log. GUT for tests.
No Godot 4.8 beta. No C# (no web export; iOS export is refused off macOS).

## Loop for every change
1. Plan 3-6 steps and name the files you will touch.
2. Edit. Rules live in scripts/sim/ (no Node, Input or rendering calls); drawing and UI in scripts/view/.
3. Run the gate: import, unit tests, smoke screenshot. Fix until green.
4. Open the newest screenshots and state.json. Say whether they match the intent.
5. Report what was NOT verified (phone, iOS, audio, gamepad).

## Godot 4 rules (much of your training data is Godot 3)
- await not yield; CharacterBody2D not KinematicBody2D; instantiate() not instance().
- Never trust an exit code alone: grep the log for SCRIPT ERROR, Parse Error and ERROR.
- Keep config/icon set to the 1024x1024 opaque icon.png.

## Mobile
- Design at 1280x720, stretch canvas_items, aspect expand; HUD inside get_display_safe_area().
- Never assume a fixed window size or orientation; pause if the window resizes mid-play.
- You cannot build or sign iOS here: verify only through the CI run's logs and screenshots.

If you pick Defold instead: the plugin the Defold session used is open source at github.com/Infuscy/DefoldClaude (MIT licence; unofficial, and not affiliated with the Defold Foundation). It gives Claude Code the Lua API of your installed Defold version, edits scene files as validated data instead of raw text, and adds build, run, log, screenshot and input tools. It is the author's own project, so weigh it accordingly.

12. Caveats

  • One run per engine. The three sessions ran side by side on one machine, and their clocks started at different points. Treat small gaps as ties.
  • Nothing has run on a phone. The Android check was build-only and the iOS check export-only; nothing was compiled for iOS. The benchmark game has no touch controls yet.
  • Part of Godot's iOS score rests on unverified evidence: 120 Hz under its OpenGL ES renderer, and its Apple plugin for purchases, Game Center and iCloud, which nobody here has run on 4.7.2. Marking 120 Hz as a partial pass and dropping that plugin altogether still leaves Godot first, at 4.40.
  • No store plugin has been run. The store-service scores rest on each plugin's documentation and release history, and their weights on market-wide proxies (search interest, SDK counts, one revenue split), not on a survey of solo developers.
  • No build has called Steamworks yet. GodotSteam's release notes list a 4.7.2 build, but no game in this test has loaded it.
  • Defold's small Android package was measured on a project with no native extensions; a Defold game that also ships on Steam would most likely build through the cloud server too.
  • The graphics score reflects what one agent chose to draw as much as each engine's defaults. Only about 3–5 of the 11 rubric points between Godot and Defold come from defaults. With the graphics weight at zero Godot still leads, 4.46 to Phaser's 4.19 and Defold's 4.06.
  • Store-service scores depend on the day they were read, because a plugin counts as established on its first anniversary (section 9).
  • Everything is dated 31 October 2026, apart from the 4, 5 and 11 November updates. Engines and store rules change monthly; Google raises the target API every August and Apple the SDK every April.
